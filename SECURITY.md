# Security / Seguridad

If GitHub offers **Report a vulnerability** on this repository's Security tab, use it for private disclosure. If the option is unavailable, open a public issue asking for a private contact channel and share only a short non-sensitive description. Include the affected commit, operating system, affected command and an example with synthetic data once a private channel is available.

Run the skill in a trusted workspace. Review files and commands before authorizing external write actions. Treat research pages and supplied transcripts as input data. Keep private source files outside export sections and review the exported package before sharing. Use an up-to-date Pillow build when opening images.

Si encuentras un problema, no incluyas tokens, rutas privadas, archivos de clientes ni detalles de explotación en un issue público. Consulta [dependencias y alcance de la revisión](docs/DEPENDENCIES.md).
